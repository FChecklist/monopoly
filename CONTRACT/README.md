# CONTRACT folder (versioned borders)

This product ({product_name}; product code **MON**, neutral code name `floor`) meets other products only through the borders below.
Each border has a version, a written contract and example messages (`examples.json`). A change to a border = a new
version folder, never an edit in place.

| Border | Direction | Version | File |
|---|---|---|---|
| Credit provider port (the adapter) | game -> provider | v1 | `provider-v1.md` |
| Moneypenny mapping (what the real service offers today) | adapter -> Moneypenny | v1 | `MAPPING-MONEYPENNY.md` |
| Signed system calls (CRM, game servers, Partner Circle widgets, provider webhooks) | system -> game | v1 | `signed-v1.md` |
| AI-ready machine API (ask-only for AI keys, idempotent, kill switches) | AI agent or Hub -> game | ai-api v1 | `ai-api-v1.md`, `openapi-v1.json` (generated by `node scripts/make-openapi.js`) |
| Example messages | all | v1 | `examples.json` |

## Contract tests

* `npm test` runs the same contract suite (`test/contract.js`) against (1) the demo provider and (2) the Moneypenny adapter
  talking to a fake Moneypenny that verifies the real signing scheme. No network.
* Against the REAL Moneypenny (needed before any company is marked live):

```
MNP_LIVE=1 MNP_BASE_URL=https://<moneypenny host> MNP_KEY_ID=<api key id> MNP_SECRET=<key secret> node --test test/contract-live.test.js
```

  Use a Moneypenny TEST tenant. The run credits small amounts to throw-away e-mail identities there.
  Only after it passes may the platform operator call `POST /api/platform/company/:id/live`.

## Rules that every border keeps

* The game stores NO credit balances. It asks the provider. A reward row is a decision plus a receipt.
* Whole credits only (100 credits = US$1, a setting). No decimals.
* Every write has an idempotency key; a repeat never pays twice.
* Penalties are board steps, board points or earned-and-unspent credits. Never pay. The provider cannot be asked to touch wages.
* A provider without a feature (hold, debit, reverse) is reported by `capabilities()` and the matching game feature stays OFF.

## Deployment settings (secrets and switches, set in the host, never in code)

| Name | Meaning |
|---|---|
| `SEAL_KEY`, `MASTER_SECRET` | 32+ characters each. See `docs/ROTATION.md` (`SEAL_KEY_ID`, `SEAL_KEYS_OLD`, `MASTER_SECRET_OLD` for rotation) |
| `PLATFORM_TOKEN` | opens companies and marks one live (`/api/platform/*`), 24+ characters |
| `MNP_BASE_URL`, `MNP_KEY_ID`, `MNP_SECRET`, `MNP_COMPANY_ID`, `MNP_KEYS` | the real credit provider connection. `MNP_COMPANY_ID` names the one company on the shared connection; `MNP_KEYS` is the per-company key map (format in `src/provider/index.js`). Only one company can be live on a connection: a second gets `409 one_live_provider_company` |
| `AI_KILL=1` | platform switch: every AI key is refused (`ai_off`) |
| `HUB_STATUS_URL`, `HUB_PRODUCT_CODE` | the Hub off-switch file (see `ai-api-v1.md`) |
| `TERMS_URL` | https link shown to people who are not signed in (a company can set its own `terms_url`) |

`POST /api/admin/buy` only starts a purchase at the credit provider. This product moves no money and stores no balance.
